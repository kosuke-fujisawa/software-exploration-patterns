# ROADMAP

このリポジトリは MVP として作られています。「実際に人が投稿するか」「どの知識分類が有効か」がまだ分からないため、最初から作り込まないことを方針にしました。

## 今できること

- Markdown で知識を書ける
- GitHub 上で読める
- GitHub Pages でも読める
- Issue フォームから意見を送れる
- PR で直接更新できる
- `main` へのマージで公開内容が自動更新される
- `catalog.json` / `patterns.json` / `all-patterns.md` / `llms.txt` / `llms-full.txt` がビルド時に生成される
- front matter の不備を CI で検出する
- 簡易な Secret Scan が CI で走る

## 今後やれること（必要になったら）

優先度は決めていません。必要性が見えてから着手します。提案は Issue へ。

### 運用

- `status: draft → reviewed` のレビュー運用を定める（誰が、何を確認したら reviewed になるのか）
- 重複した知識の統合手順を決める
- 分類（episodes / heuristics / patterns / sources）の見直し。運用してみて合わなければ変える
- 共同 Maintainer の追加

### 自動化

- Issue から Draft PR を自動生成する（投稿のハードルをさらに下げる）
- タグ別・type 別のインデックスページを自動生成する
- パターン間のリンクをグラフとして可視化する
- リンク切れ検査を CI に追加する
- `updated` を最終コミット日から自動更新する

### LLM 関連

- LLM による重複検出・分類提案（提案のみ。自動マージはしない）
- 「この仕様に適用できる探索パターンを提示する」ための、使い方の例とプロンプト集
- MCP サーバなど、外部ツールから知識を引ける口

### コンテンツ

- 英語版（現在は日本語を基本にしている）
- 各パターンへの反例の収集
- 出典の拡充。特に `status: stub` の項目

### サイト

- 全文検索（現状は未実装。ブラウザの検索と GitHub の検索で足りるかを見てから判断する）

## 意図的に入れなかったもの

- 複雑な Bot / 自動分類 — 投稿が集まる前に作っても、何が必要か分からないため
- 凝った UI — 保守コストが知識の蓄積より重くなることを避けるため
- 厳格なスキーマ検証 — 投稿のハードルを上げないため。検査は最低限にとどめている
- 生成物（`catalog.json` など）のコミット — PR ごとの衝突と commit-back ループを避けるため、ビルド時生成にしている
