# 0001 Markdown を Source of Truth にする

- 状態: Accepted
- 日付: 2026-10-04

## 背景

この知識ベースは、人間が読むだけでなく、LLM から利用されることを前提にしている。また、Maintainer がいなくなっても知識が残ることを目標にしている。

## 決定

Markdown ファイルを一次情報とする。具体的には次の方針を取る。

- **1ファイル1知識単位**とする
- すべての知識ファイルに YAML front matter でメタデータを付ける
- 関連知識は、front matter（`related` / `sources` / `episodes`）と本文中の相対リンクの両方でつなぐ
- **HTML だけに情報を閉じ込めない。** サイトは Markdown から生成される派生物であり、正本ではない
- **JavaScript がないと本文が取得できない構成にしない**
- 過度に装飾しない

## 理由

- クローンすれば、特別なツールなしに全内容が読める。サイトや GitHub が失われても知識は残る
- LLM に渡すとき、Markdown はそのまま読めて、front matter が構造化された手がかりになる
- Git の履歴が、そのまま知識の更新履歴になる
- 独自フォーマットや DB を採用すると、移行コストが知識の寿命を縮める

## 帰結

- サイト側の機能（検索、フィルタなど）は、Markdown から生成できる範囲に制限される
- メタデータの一貫性は、`scripts/build_catalog.py --check` による検査と人間のレビューで担保する
- 機械可読な派生物（`catalog.json` など）はビルド時に生成し、リポジトリにはコミットしない
