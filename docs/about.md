# このプロジェクトについて

Software Exploration Patterns は、ソフトウェア開発における**探索知**を、分野を越えて集め、共同で更新するオープンな知識ベース（Living Knowledge Base）です。

要求工学 / ソフトウェアテスト / QA / アジャイル / Product Management / UX・UX Research / ソフトウェア設計 / Safety・Reliability Engineering —— これらに散らばっている「気づき方」の知識を、特定の方法論の所有物にせず、横断的に整理することを目指しています。

## 探索知とは何か

ここでいう探索知とは、たとえば次のような活動に関する知識です。

- 何かがおかしいことに気づく
- 前提を疑う
- 不明点を見つける
- 詳しい人に聞く
- 現場を見る
- ユーザー体験を確認する
- Failure State から逆算する
- リスクを見つける
- 要求・設計・実装・テスト・運用のどこで扱うべきか問い直す
- 理解を更新する

どれも、分野ごとに別の名前で語られていたり、「経験を積めば分かる」として書き残されてこなかったりするものです。

## なぜ作るのか

ソフトウェア開発では、要求・仕様・ユーザー理解・リスク・品質について、最初から完全に正しい理解を作ることはできません。

重要なのは、固定された要求を精緻に分析することだけではなく、**ズレ・未知・リスクに早く気づき、理解を更新していくこと**です。

そのための知識は現在、複数の分野に分散しています。同じ気づき方が、分野ごとに別の名前で呼ばれていたり、どこにも書き残されていなかったりします。このリポジトリは、それらを一か所に持ち寄って比較・統合できるようにするための場所です。

## 大切にしていること

### 正解集ではない

ここに掲載するものは「この通りにすれば正しい要求が得られる」という手順書ではありません。

不確実な状況で、

- 次に何を見れば理解が進むか
- 何を疑えばよいか
- 誰に聞けばよいか

を考えるための知識です。掲載されている内容が、あなたの状況で有効とは限りません。**効かなかったという報告も、同じくらい価値があります。**

### 探索は反復する

探索は一度で終わる作業ではなく、次のように反復します。

```text
理解する → 疑問が生まれる → 情報を取りに行く → 理解が変わる → 次の探索先が変わる
```

知識の分類（Episodes / Heuristics / Patterns / Sources）も同じで、一方向に昇格していく階段ではありません。エピソードからヒューリスティックが生まれ、複数のエピソードからパターン候補が立ち上がり、既存研究がパターンを書き換え、反例がパターンの適用範囲を狭め、読んだパターンが次の探索を生みます。

### テストに限定しない

**これはテストを否定するプロジェクトではありません。** テストは、探索で見つけたリスクに対する有力な保証手段のひとつです。

言いたいのは、保証手段がテストだけではない、ということです。テスト、レビュー、要求変更、設計変更、実装上の制約、静的解析、自動化、可観測性、運用・モニタリング —— これらを、**探索によって得たい証拠に応じて選ぶ**こと。そして「このリスクをどこで受け止めるのが妥当か」を問い直すこと自体が、探索知です。

たとえば、組み合わせが爆発してテスト件数が現実的でなくなったとき、削減技法を適用する前に「この自由度は本当に必要か」と要求へ返せることがあります（[リスクを設計へ返す](../patterns/return-risk-to-design.md)）。

### 共同知識である

これは特定個人の方法論を公開するリポジトリではありません。

誰でも、新しい知識を提案し、既存の知識を修正し、反例を加え、出典を補い、重複を指摘できます。Maintainer の役割は、知識を所有することではなく、整理・統合・レビューです（[GOVERNANCE.md](../GOVERNANCE.md)）。

コンテンツは [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/deed.ja) なので、誰でも許諾なしに Fork して継続できます。特定の人がいなくなっても知識が残ることを、設計目標のひとつにしています。

### 出典と来歴を大切にする

CC0 に**法的な帰属義務はありません**。それでもこのプロジェクトでは、**知識がどこから来たのかを追跡できること**を別の価値として重視します。

既存研究・書籍・記事・方法論は [Sources](../sources/) に、もとになった経験は [Episodes](../episodes/) に記録し、パターンからたどれるようにしています。「その話はすでに○○で論じられている」という指摘は、新しいパターンの投稿と同じくらい歓迎されます。

### まだ初期段階である

現在掲載されているパターンは初期サンプルです。サイトが整って見えることで、体系として完成している・検証済みである・標準である、と受け取らないでください。

掲載内容は継続的に検証・修正・統合されます。それが Living Knowledge Base であるということです。
